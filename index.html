Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

We can find a Bezier curve that fits a given set of control points using De Casteljau’s algorithm. It relies on a recursive step: take a vector of control points, linearly interpolate between each consecutive pair of points with a parameter t, and return the results as a vector of intermediate points. This is repeated until we are left with just one point.

I implemented this recursive step in Part 1. I first check the length of the input vector, points. If the vector has length 1, the function returns it immediately; otherwise, the function cycles through the vector and linearly interpolates between consecutive points, storing the resultant point in a vector called im_points. Once we cycle through the entire vector, im_points, the vector of intermediate control points, is returned.

Part 2: Bezier surfaces with separable 1D de Casteljau

Evaluating Bezier surfaces involves taking a square grid of points lying in 3D space. We extend de Casteljau’s algorithm for Bezier curves to this case, applying it across rows using parameter u, then to the vector of resultant points using the parameter v, to arrive at a point on the Bezier surface.

To implement this, I first finished defining the function evaluate1D, which completes de Casteljau's algorithm by applying recursion. I then used evaluate1D on each row of the input grid contolPoints with parameter u, recording the results in a vector called points_u. I then apply a last round of de Casteljau to this vector using parameter v, which gives me the final desired point.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-Weighted Vertex Normals

Calculating area-weighted vertex normals requires three things: the vertex's neighboring faces, their area, and their normal vectors.

To find all the neighboring faces, I repurposed the printNeighborPositions example in the HW2 primer, and recorded the positions of neighboring vertices in a vector vertices instead of printing them out. The next step explains why this vertex information is sufficient.

Next, I needed to calculate the area and normals of each face. The area of the parallelogram formed by two vectors can be calculated by taking the norm of their cross product; and a triangle's area is just half of that. The normal vector is defined as the cross product of those same two vectors divided by its norm. Thus, I can derive a formula for the area-weighted normal of a face:

\[\text{Area} * \text{Normal Vector}\] \[ \begin{aligned} &= \frac{|| \mathbf{v}_1 \times \mathbf{v}_2 ||}{2} * \frac{\mathbf{v}_1 \times \mathbf{v}_2}{|| \mathbf{v}_1 \times \mathbf{v}_2 ||} \\ &= \frac{\mathbf{v}_1 \times \mathbf{v}_2}{2} \end{aligned} \]

In my code, the result of this calculation would be off by negative 1 due to winding order, so I just divided by -2 instead to account for that.

I implemented this calculation in code, and applied it to each neighboring vertex, recording the results in the vector normals. To arrive at the final result, sum up all the vectors and divide by the number of neighboring faces.

Part 4: Edge Flip

Edge flipping is a process of relinking existing elements to redefine the shared edge between two triangles. Because no elements are created in the process, but an edge has to change places and two completely different triangles arise, I defined iterators referencing the existing elements of the mesh first before relinking anything. Specficially, since this is a local operation, I only consider the two triangles that share the input edge, and their elements. I created a drawing and labeled all mesh elements accordingly, without loss of generality, to refer to when defining iterators. I then referred to the same drawing, with the new edge added on, to setNeighbors for all the half edges. I then reassigned half edges to the other mesh elements.

This took me a while to figure out, as I initially missed the requirement of not creating new elements, and also referenced the elements of the mesh in a very roundabout way, causing issues because relationships would get messed up along the way. Creating a diagram with clear labels, and going about referencing and redefining elements step by step helped me succeed with the implementation. Moreover, for this and the next task, I made minimal changes to the outer half edges, preserving their existing connections to the surrounding faces, to ensure that the method only makes local changes.

Part 6: Loop Subdivision for Mesh Upsampling

Loop subdivision is the process of splitting each triangle in a mesh into four smaller ones to achieve upsampling, resulting in a smoother mesh. To achieve this more efficiently, we don't actually go about splitting each triangle into four, but rather iterate through all the mesh elements, first splitting every edge, creating new vertices, then flipping edges that connect an old and new vertex.

Loop subdivision not only creates many new vertices, but alters the positions of existing ones. Thus, the first step in my implementation was to use the given formulas to calculate updated positions of existing vertices and newly created vertices, which I stored in the newPosition attribute of the existing vertices and edges that were to be split.

Then, I moved on to actually splitting the edges, which simply involved iterating over each edge in the mesh and calling splitEdge. A big note here is that we should only iterate over the original edges of the mesh, and not the newly created ones from splitting edges! When I was looping over the edges in the previous step to find the new vertex positions, I also created a vector to store these existing edges called original_edges, which I iterated over in this step. I was initially skeptical if this would work, but realized that because new vertices would be created as we split, and that we were only iterating through existing edges, the end result of this step would look something like the diagram in the task.

Next, I flipped edges which connected an old vertex to a new vertex. To record if a vertex is old or new, I set the isNew attribute to false for existing vertices while updating their positions in step 1, and set it to true for new vertices I created while splitting edges in the last step. I then iterated through all edges, flipping them if they had both old and new vertices.

Lastly, I updated all vertices with their new positions!
